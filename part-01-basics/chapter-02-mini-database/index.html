    第2章：极简数据库内核原型设计¶

    章节定位¶

    本章学什么？¶

    在第1章你看到了数据库内核的全景地图，本章你将亲手实现第一个迷你数据库。

    你将学习： 1. 如何设计一个数据库的最小可用原型（MVP） 2. 数据在内存中如何组织和存储 3. 如何实现插入（INSERT）和查询（SELECT）操作 4. 什么是"引擎接口"——数据库内核的设计模式

    能解决什么问题？¶

    学完本章后，你会拥有一个真正能跑起来的数据库（虽然功能极简）。这是你数据库内核开发之路的第一个里程碑。

    和前后章节的关联¶

    第1章(全景地图) → 【第2章(迷你原型)】→ 第3章(文件存储，不再丢数据)

    第1章只是"看"数据库内核长什么样，第2章是"做"一个最简单的。从第3章开始，我们会逐步把这个迷你数据库升级成一个越来越完整的数据库。

    详尽理论¶

    一、概念解释¶

    1.1 什么是最小可用原型（MVP）？¶

    MVP = Minimum Viable Product，最小可用产品。

    意思是用最少的代码，实现最核心的功能，让整个系统能跑通。

    对于数据库来说，MVP需要： - 能创建表（CREATE TABLE） - 能插入数据（INSERT） - 能查询数据（SELECT）

    更新（UPDATE）和删除（DELETE）可以后续再加上。

    1.2 数据库内核的"引擎"设计模式¶

    在工业级数据库中（如MySQL），有一个重要的设计模式：可插拔存储引擎。

    MySQL Server（上层SQL处理）
    │
    ├── 存储引擎接口（统一的API）
    │
    ├── InnoDB 引擎（支持事务、行锁）
    ├── MyISAM 引擎（不支持事务、表锁）
    └── Memory 引擎（数据存内存，重启就丢）

    为什么这样设计？ - 不同的应用场景需要不同的存储特性 - 通过统一接口，可以随时切换引擎 - 开发者可以写自己的引擎

    我们在本章就会模仿这个设计，定义一个引擎接口。

    1.3 数据在内存中的组织方式¶

    在迷你数据库中，数据需要一种数据结构来组织。我们选择最简单的：嵌套HashMap。

    表名 "student"
    │
    └── 行数据（按主键索引）
        ├── "100" → ["100", "张三", "20"]
        ├── "101" → ["101", "李四", "22"]
        └── "102" → ["102", "王五", "19"]
    • 外层 Map：表名 → 表数据
    • 内层 Map：主键 → 行数据（字符串数组）

    这个设计虽然简单，但体现了数据库的核心思想： 通过某种键（主键）快速找到对应的数据行。

    二、原理详解：迷你数据库的架构¶

    ┌─────────────────────────────────────────┐
│            用户输入命令                    │
│     INSERT INTO student VALUES ...       │
│     SELECT * FROM student                │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│           命令解析器（简易版）              │
│   把命令字符串拆开，识别是什么操作          │
│   提取表名、数据值等信息                    │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│           存储引擎接口                     │
│   定义了 insert / select 等标准方法        │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│         HashMap存储引擎（具体实现）         │
│   用嵌套HashMap模拟数据存储                │
│   负责真正存取数据                         │
└─────────────────────────────────────────┘

    三、核心流程：INSERT操作的完整步骤¶

    以这条命令为例：INSERT INTO student VALUES 100 张三 20

    第1步：命令解析器读取用户输入
  → 把字符串按空格拆分
  → 得到：["INSERT", "INTO", "student", "VALUES", "100", "张三", "20"]

第2步：识别操作类型
  → 第一个单词是 "INSERT"
  → 所以这是一条插入命令

第3步：提取表名
  → INTO 后面的单词：student
  → 目标表名 = "student"

第4步：提取数据值
  → VALUES 后面的所有单词：["100", "张三", "20"]
  → 这些就是要插入的数据

第5步：调用引擎的 insert 方法
  → 引擎.insert("student", ["100", "张三", "20"])

第6步：引擎内部处理
  → 找到（或创建）student表的存储空间
  → 以 "100" 为主键，存入 ["100", "张三", "20"]
  → 返回插入成功

    四、常见误区¶

    误区1：以为这个迷你数据库能替代MySQL¶

    错误：学完本章就能用自己写的数据库做项目了。

    正确：本章的数据库只有几十行代码，功能极简。它没有事务、没有索引、没有持久化、不支持并发。它的价值在于帮你理解数据库内核的最小骨架，而不是实际使用。

    误区2：以为数据存在HashMap里就是"内存数据库"¶

    错误：数据在HashMap里 = 内存数据库。

    正确：真正的内存数据库（如Redis）有复杂的过期策略、持久化机制、集群方案。我们的HashMap只是教学用的简化模型。从第3章开始，数据会逐步存到真正的文件里。

    误区3：跳过命令解析，直接用Java方法调用¶

    错误：既然是Java项目，直接写 engine.insert("student", data) 就好了，为什么要做命令解析？

    正确：命令解析就是SQL解析的雏形！第8-10章会专门学词法分析和语法分析。现在先接触简单的命令解析，为后续打基础。

    Java实战Demo¶

    Demo目标¶

    实现一个真正可交互的迷你数据库，支持以下命令： - CREATE TABLE 表名 列1 列2 ... - INSERT INTO 表名 VALUES 值1 值2 ... - SELECT * FROM 表名 - SELECT * FROM 表名 WHERE 列 = 值 - EXIT 退出

    项目结构¶

    chapter-02-mini-database/demo/
├── pom.xml
└── src/main/java/com/ourdatabase/
    ├── 迷你数据库.java              (主程序，交互入口)
    ├── 存储引擎接口.java            (引擎接口定义)
    └── HashMap存储引擎.java         (引擎的具体实现)

    运行步骤¶

    cd chapter-02-mini-database/demo
mvn compile
mvn exec:java -Dexec.mainClass="com.ourdatabase.迷你数据库"

    运行示例¶

    欢迎使用迷你数据库！
支持的命令：
  CREATE TABLE 表名 列1 列2 ...
  INSERT INTO 表名 VALUES 值1 值2 ...
  SELECT * FROM 表名
  SELECT * FROM 表名 WHERE 列 = 值
  EXIT

miniDB> CREATE TABLE student id name age
  -> 表 'student' 创建成功，列: [id, name, age]

miniDB> INSERT INTO student VALUES 100 张三 20
  -> 插入成功，主键=100

miniDB> INSERT INTO student VALUES 101 李四 22
  -> 插入成功，主键=101

miniDB> SELECT * FROM student
  -> 查询结果（共 2 条）：
     [id=100, name=张三, age=20]
     [id=101, name=李四, age=22]

miniDB> SELECT * FROM student WHERE id = 100
  -> { id=100, name=张三, age=20 }

miniDB> EXIT
  -> 再见！

    本章总结¶

    核心知识点¶

    序号 知识点 说明
    1 MVP设计思想 用最少代码实现最核心功能
    2 可插拔引擎模式 接口定义标准，实现可以切换
    3 数据的内存组织 嵌套HashMap，主键索引
    4 命令解析流程 拆分字符串→识别操作→提取参数→执行

    Demo功能复盘¶

    功能 实现方式 后续升级方向
    创建表 HashMap记录表结构 第4章：用页管理
    插入数据 HashMap存储行数据 第3章：持久化到文件
    查询数据 遍历匹配 第7章：B+树索引加速
    命令解析 字符串拆分 第9章：词法分析器
