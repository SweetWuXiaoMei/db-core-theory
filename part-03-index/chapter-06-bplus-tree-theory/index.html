    第6章：数据结构·B+树入门（索引核心底层）¶

    章节定位¶

    本章学什么？¶

    前5章中，查询数据都是全表扫描（一行一行检查）。当数据量达到百万级别时，这种方式会非常慢。

    本章学习B+树——数据库中最重要的索引数据结构，它能让查询从O(n)变成O(log n)。

    你将学习： 1. 为什么需要索引？（从全表扫描到快速查找） 2. 二分查找的思想 3. 从二分查找到二叉搜索树 4. 从二叉搜索树到B树（为什么磁盘需要多叉树？） 5. 从B树到B+树（数据库的最终选择）

    和前后章节的关联¶

    第5章(缓冲池) → 【第6章(B+树理论)】→ 第7章(B+树Java实现)

    详尽理论¶

    一、概念解释¶

    1.1 为什么需要索引？¶

    没有索引（全表扫描）： 

    SELECT * FROM student WHERE id = 5000000;

数据库要做：读取第1行 → 检查id → 不是500万
            读取第2行 → 检查id → 不是500万
            ...
            读取第500万行 → 检查id → 找到了！

磁盘读取次数：可能几百万次
时间：几十秒甚至几分钟

    有索引（B+树）： 

    同上查询：
B+树搜索：根节点 → 中间节点 → 叶子节点 → 找到位置 → 读磁盘
磁盘读取次数：3-4次（树的高度）
时间：几毫秒

    性能差异：几十万倍！

    1.2 二分查找：索引思想的来源¶

    假设有100万个有序ID：1, 2, 3, ..., 999999, 1000000

    查找ID=777777： 

    第1次：看中间位置（50万），777777 > 50万 → 在右半部分
第2次：看右半部分中间（75万），777777 > 75万 → 在更右边
第3次：看更右部分中间（87.5万），777777 < 87.5万 → 在左边
...
每次把查找范围缩小一半！

    复杂度：O(log n)，100万数据只需20次比较！（log₂(1,000,000) ≈ 20）

    1.3 为什么不能用二分查找的数组？¶

    二分查找需要在有序数组中进行。但数据库数据经常增删改：

    • 在数组中间插入一个元素 → 后面的所有元素都要移动 → O(n)！
    • 频繁插入/删除 → 性能灾难

    我们需要一种支持动态插入/删除，同时又能快速查找的数据结构。

    二、原理详解：从二叉树到B+树的进化¶

    2.1 二叉搜索树（BST）¶

            8
       / \
      3   10
     / \    \
    1   6    14
       / \   /
      4   7 13
    • 左子节点 < 父节点 < 右子节点
    • 查找：从根开始，比大小决定向左还是向右
    • 复杂度：O(log n)（平衡时），O(n)（退化成链表时）

    问题1：如果插入顺序是1,2,3,4,5,6...，树会退化成一条链表！

    问题2：每个节点只有2个子节点 → 树很"高" → 磁盘IO次数多

    2.2 B树（多路搜索树）¶

    二叉树的每个节点只有2个子节点。B树让每个节点有多个子节点（比如100个），树就变"矮"了。

              [30 | 60]
         /    |    \
   [10|20] [40|50] [70|80|90]
   /  |  \  /  |  \  /  |  |  \
  ... ... ... ... ... ... ... ... ...
    • 一个节点可以存多个键值和多个子节点指针
    • 树的高度大大降低 → 磁盘IO次数急剧减少
    • 每个节点的大小 = 一个磁盘页的大小（巧妙！）

    2.3 B+树（B树的数据库优化版）¶

    B+树和B树的关键区别：

    特性 B树 B+树
    数据存放位置 所有节点都存数据 只有叶子节点存数据
    内部节点作用 存数据+做索引 只做索引（导航）
    叶子节点连接 不连接 用链表连接
    范围查询 需要中序遍历 叶子链表直接扫描
    数据库使用 ❌ ✅

    B+树结构示意：

                   [30 | 60]               ← 内部节点（只做导航）
              /    |    \
        [10|20] [40|50] [70|80]        ← 内部节点（只做导航）
        /  |  \  /  |  \  /  |  \
       ○ → ○ → ○ → ○ → ○ → ○ → ○ → ○  ← 叶子节点（存数据+链表连接）
      (1) (10)(20)(30)(40)(50)(60)(70)  ← 所有叶子节点通过链表连接

    B+树的优势：

    1. 内部节点只存键值（不存数据）→ 一个节点能存更多键 → 树更矮
    2. 叶子节点有链表 → 范围查询极快（找到起点，沿链表扫描即可）
    3. 查询稳定 → 任何查询都走到叶子节点，O(log n)可预测

    2.4 B+树的阶（Order）¶

    B+树的"阶"是指一个节点最多有多少个子节点。

    阶 m = 4 的B+树：
- 内部节点最多存 3 个键值（m-1 = 3）
- 内部节点至少有 2 个子节点（⌈m/2⌉ = 2）
- 叶子节点最多存 3 个数据项
- 叶子节点至少有 2 个数据项

    阶和磁盘页大小的关系： - 一个节点 = 一页（16KB） - 阶的大小取决于：键值大小 + 指针大小 - 如果每对(键+指针)占16字节，那一个16KB页能存约1000个键 → 阶≈1000

    三、核心流程：B+树的操作¶

    3.1 查找（Search）¶

    查找 key=40： 

    步骤1：从根节点开始
  [30 | 60]
  key=40, 30 < 40 <= 60 → 走中间分支

步骤2：到中间子节点
  [40 | 50]
  key=40, 40 <= 40 → 走最左分支

步骤3：到叶子节点
  叶子中有 40 → 找到！

    3.2 插入（Insert）¶

    插入 key=25 到已有B+树：

步骤1：找到应该插入的叶子节点（通过查找流程）

步骤2：在叶子节点中插入 25

步骤3：如果叶子节点满了（超过最大键值数）：
  → 分裂（Split）：把叶子节点一分为二
  → 把中间键值提升到父节点

步骤4：如果父节点也满了：
  → 继续向上分裂
  → 最坏情况：一直分裂到根节点，树的高度+1

    3.3 删除（Delete）¶

    删除 key=25：

步骤1：找到key所在的叶子节点

步骤2：从叶子节点中删除 25

步骤3：如果叶子节点键值数少于最小值：
  → 尝试从兄弟节点借一个（旋转）
  → 如果兄弟也不够，和兄弟合并
  → 父节点中的键值也要更新

步骤4：如果合并导致父节点键值不够：
  → 继续向上处理
  → 最坏情况：一直合并到根节点，树的高度-1

    四、常见误区¶

    误区1：B+树就是"二叉树+"¶

    错误：B+树是二叉树的一种增强版。

    正确：B+树是多路搜索树，每个节点有很多子节点。"B"不是"Binary"（二分），而是"Balanced"（平衡）或者干脆是发明者的名字（Bayer）。

    误区2：索引越多越好¶

    错误：给每一列都建索引。

    正确：索引会占用额外空间，且每次INSERT/UPDATE/DELETE都需要更新索引。冗余索引会降低写入性能。

    误区3：B+树的高度是固定的¶

    错误：B+树的高度和二叉树一样，不稳定。

    正确：B+树是自平衡的，所有叶子节点在同一层。插入和删除时会自动分裂/合并来保持平衡。

    本章总结¶

    序号 知识点 说明
    1 索引的价值 让查询从O(n)变成O(log n)
    2 二分查找 索引思想的来源
    3 B+树 vs B树 数据只存叶子节点 + 叶子链表
    4 阶（Order） 一个节点最多有多少子节点
    5 分裂和合并 B+树保持平衡的核心机制
