# 第4章：数据页管理·数据库物理存储核心

## 章节定位

### 本章学什么？

第3章学会了把数据存到文件里。但如果每行数据都随意写入，文件会变得像垃圾堆一样混乱。本章学习数据库物理存储最核心的设计——**数据页（Page）**。

你将学习：
1. 什么是数据页？为什么数据库要按"页"来组织数据？
2. 页的内部结构（页头、页体、槽目录）
3. 如何在页中插入、查找、删除数据行
4. 如何管理多个页（页分配、页链表）

### 能解决什么问题？

学完本章后，你的数据将以**整齐的、固定大小的"页"**来组织，而不是零散的字节流。这是B+树索引（第6-7章）和缓冲区管理（第5章）的基础。

```
第3章(文件IO) → 【第4章(数据页)】→ 第5章(缓冲区) → 第6-7章(B+树)
```

## 详尽理论

### 一、概念解释

#### 1.1 什么是数据页（Page）？

**数据页是数据库读写磁盘的最小单位。**

想象一本书：
- 书由"页"组成，每页大小相同（比如A4纸）
- 你不能读"半页"，要读就是一整页
- 每页上有行文字，但不能跨页（一行文字不能一半在第3页、一半在第4页）

数据库也是这样：
- 数据文件被分成很多**固定大小的页**（通常4KB、8KB或16KB）
- 每次读写至少一整页（不能读半页）
- 一行数据不能跨页存储（这个限制很重要）

```
数据文件 "student.db"（假设页大小=4KB）
┌──────────────────┐
│   页0 (4096字节)  │ ← 第0页
├──────────────────┤
│   页1 (4096字节)  │ ← 第1页
├──────────────────┤
│   页2 (4096字节)  │ ← 第2页
├──────────────────┤
│      ...         │
└──────────────────┘
```

#### 1.2 为什么用"页"而不是直接写字节？

| 无页设计（第3章） | 有页设计（第4章） |
|-------------------|-------------------|
| 行随意写入，文件很快碎片化 | 每页大小固定，整齐有序 |
| 删除一行后留下空洞 | 页内可以整理碎片 |
| 缓存管理困难 | 可以按页缓存（第5章核心） |
| 索引无法定位 | 索引存页号，精确定位（第7章） |

#### 1.3 页的内部结构（以MySQL InnoDB为例）

```
一页（16KB = 16384字节）的内部结构：
┌──────────────────────────────────┐
│         页头（Page Header）       │  ← 38字节，存页的元信息
├──────────────────────────────────┤
│         行记录（User Records）    │  ← 实际数据
│   行1: [100, 张三, 20]           │  ← 从页尾向前增长！
│   行2: [101, 李四, 22]           │
├──────────────────────────────────┤
│         空闲空间（Free Space）     │  ← 还可以插入新行
├──────────────────────────────────┤
│         页目录（Page Directory）  │  ← 记录每组的最大键值
├──────────────────────────────────┤
│         页尾（Page Trailer）      │  ← 8字节，校验和
└──────────────────────────────────┘
```

**关键设计**：行记录从页尾向前增长，页目录从页头向后增长，中间是空闲空间。这样两者不会冲突。

### 二、原理详解

#### 2.1 页号的寻址

每个页有一个唯一的**页号**，从0开始。

```
文件中的字节位置 = 页号 × 页大小

例如：页大小=4096字节
  页2的数据在字节位置：2 × 4096 = 8192
  页5的数据在字节位置：5 × 4096 = 20480
```

这就是为什么B+树索引中存的是**页号**，因为通过页号可以O(1)计算出文件位置。

#### 2.2 页头（Page Header）存什么？

| 字段 | 说明 | 字节数 |
|------|------|--------|
| 页号 | 这一页的编号 | 4 |
| 页类型 | 数据页/索引页/Undo页等 | 2 |
| 上一页号 | 前一页（页链表） | 4 |
| 下一页号 | 后一页（页链表） | 4 |
| 行记录数 | 当前页有多少行数据 | 2 |
| 空闲空间偏移 | 空闲空间的起始位置 | 2 |

#### 2.3 行在页中如何存储？

```
页内行的内存布局（Compact行格式）：
┌──────────────────────────────────┐
│ 变长字段长度列表（如果有VARCHAR）  │
├──────────────────────────────────┤
│ NULL值标记（哪些列是null）        │
├──────────────────────────────────┤
│ 记录头（5字节）                   │
│  - 下一条记录的偏移量             │
│  - 记录类型                      │
│  - 该记录被哪个事务修改            │
├──────────────────────────────────┤
│ 列1数据 │ 列2数据 │ 列3数据 ...  │
└──────────────────────────────────┘
```

**记录之间通过"下一条记录偏移量"串成链表**，这就是"页内行链表"。

### 三、常见误区

#### 误区1：页大小越大越好

**错误**：设成64KB甚至128KB，一次读更多数据。

**正确**：页太大 → 浪费内存（即使只读1行也要加载整个64KB页）；页太小 → 页管理开销大（很多页头元数据）。MySQL默认16KB，是一个经过大量实践验证的平衡值。

#### 误区2：删除一行会立即回收空间

**错误**：DELETE后空间马上释放。

**正确**：行只是被标记为"已删除"，空间不会立即回收。只有在页整理（Page Reorganize）时才真正释放。这就是为什么DELETE后文件可能不会变小。

## Java实战Demo

### Demo目标

实现一个数据页管理器，支持：
1. 创建固定大小的数据页
2. 在页中插入行
3. 从页中查找行
4. 页的序列化/反序列化（存到文件和从文件读取）

### 项目结构

```
chapter-04-page-management/demo/
├── pom.xml
└── src/main/java/com/ourdatabase/page/
    ├── 数据页.java           (核心：页的数据结构)
    ├── 页管理器.java          (管理多个页的分配和释放)
    └── 页管理演示.java        (主程序)
```

### 运行步骤

```bash
cd chapter-04-page-management/demo
mvn compile
mvn exec:java -Dexec.mainClass="com.ourdatabase.page.页管理演示"
```
