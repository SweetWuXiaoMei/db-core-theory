# 第3章：数据存储原理·文件操作基础

## 章节定位

### 本章学什么？

第2章的迷你数据库有一个致命缺陷：**程序一关，数据全部丢失**。因为数据存在内存（HashMap）里，内存断电就清空。

本章你将学习如何把数据真正**持久化到磁盘文件**中，让你的数据库在重启后还能找回数据。

你将学习：
1. 计算机是如何读写文件的（二进制、字节流）
2. Java的三种文件操作方式（顺序读写、随机读写、NIO）
3. 如何把数据库的行数据转换成字节存到文件里（序列化）
4. 如何从文件里读回数据（反序列化）

### 能解决什么问题？

学完本章后，你的数据库数据将**真正保存到硬盘上**。关掉程序再打开，数据还在。

### 和前后章节的关联

```
第2章(内存HashMap) → 【第3章(文件持久化)】→ 第4章(数据页管理)
```

第2章数据在内存中，一关就丢。第3章学会存文件。第4章会学习数据库如何以"页"为单位来组织文件中的数据。

## 详尽理论

### 一、概念解释

#### 1.1 计算机如何存储数据？

计算机的存储分为两层：

```
┌────────────────────────────────┐
│         内存（Memory/RAM）      │  ← 快！但断电就丢
│  速度：纳秒级（0.000000001秒）  │
│  容量：GB级别（16GB、32GB）     │
│  特点：程序运行时数据在这        │
└────────────────────────────────┘
              ↕ 数据搬运
┌────────────────────────────────┐
│        磁盘（Disk/SSD/HDD）     │  ← 慢！但断电不丢
│  速度：微秒~毫秒级              │
│  容量：TB级别（512GB、1TB）     │
│  特点：数据永久保存在这          │
└────────────────────────────────┘
```

**数据库的核心工作之一**就是在内存和磁盘之间搬运数据。

#### 1.2 什么是"文件"？

文件就是磁盘上一段有名字的连续数据。

```
文件 "student.db"
┌────────────────────────────────┐
│ 字节:  [01001001 01000100 ...] │
│ 大小:  4096 字节                │
│ 位置:  /data/student.db        │
└────────────────────────────────┘
```

所有文件本质上都是**一串字节（byte）**。数据库文件、图片文件、音乐文件，都是字节串。区别只在于**如何解读这些字节**。

#### 1.3 什么是序列化和反序列化？

**序列化**：把内存中的数据结构（对象、数组）转换成一串字节，以便存到文件里。

```
内存中的数据：                    序列化后的字节：
String[] {"100", "张三", "20"}  →  [7字节]100[6字节]张三[2字节]20
```

**反序列化**：把文件中的字节串还原成内存中的数据结构。

```
文件中的字节：                    反序列化后：
[7字节]100[6字节]张三[2字节]20   →  String[] {"100", "张三", "20"}
```

数据库内核大量使用序列化/反序列化来读写数据。

### 二、原理详解：Java文件IO三种方式

#### 2.1 顺序文件流（FileOutputStream / FileInputStream）

像磁带一样，只能从头到尾顺序读写。

```
写入：数据 → [字节1][字节2][字节3]... → 文件末尾
读取：文件开头 → [字节1][字节2][字节3]... → 读完
```

**优点**：简单直观
**缺点**：不能随机跳到某个位置读写（数据库肯定不能这样，因为你需要快速找到某一行）

#### 2.2 随机访问文件（RandomAccessFile）

像一个可以随意拖动进度条的视频播放器。

```
文件: [字节0][字节1][字节2]...[字节999]...[字节4095]
                                      ↑
                          可以随时跳到第1000字节处读写
```

**关键方法**：
- `seek(位置)` —— 把读写指针移动到指定位置
- `read()` —— 从当前位置读
- `write()` —— 从当前位置写

**为什么数据库需要随机访问？**
- 查询 `WHERE id = 100`，需要直接跳到 id=100 所在的位置
- B+树索引指向的页面位置，需要精确跳过去读

#### 2.3 NIO（New IO，更高效的IO方式）

NIO是Java 1.4引入的更高效的文件操作方式。

核心概念：
- **Buffer（缓冲区）**：一块内存区域，批量读写
- **Channel（通道）**：连接文件和Buffer的管道

```
文件 ←→ Channel ←→ Buffer ←→ 程序
         (通道)     (缓冲区)
```

NIO的优势是"零拷贝"和"内存映射"，第5章会用到。

### 三、核心流程：写入一行数据到文件

```
步骤1: 有一行数据要写入
  数据 = {"100", "张三", "20"}

步骤2: 序列化这行数据
  先写长度，再写内容（这样读的时候知道每个字段多长）
  │ 3字节 │100│ 6字节 │张三│ 2字节 │20│
  │  长度  │内容│  长度  │内容 │  长度  │内容│

步骤3: 写入文件
  打开文件 → 定位到写入位置 → 写入字节 → 关闭文件

步骤4: 写入完成，数据持久化到磁盘
```

**"长度+内容"这种格式非常关键**，它让读取方知道每个字段的开始和结束位置。

### 四、常见误区

#### 误区1：flush()之后就一定写到磁盘了

**错误**：调用了 `fileOutputStream.flush()` 就以为数据到磁盘了。

**正确**：`flush()` 只是把数据从Java程序的缓冲区推到操作系统的缓冲区。操作系统可能还会缓存一段时间才真正写到磁盘。只有调用 `fsync`（或 `FileDescriptor.sync()`）才能确保数据落盘。

#### 误区2：忘记关闭文件流

**错误**：打开文件用完就不管了。

**正确**：不关闭文件流会导致：
- 文件被锁定，其他程序无法访问
- 内存泄漏
- 数据没写完就丢了

**一定要用 try-with-resources**（Java 7+的语法），自动关闭文件。

#### 误区3：把所有数据写到一个文件里就行

**错误**：一个数据库就一个文件。

**正确**：真实数据库有很多文件：
- 数据文件（.ibd）：存实际数据
- 日志文件（redo log、undo log）：存操作日志
- 元数据文件：存表结构信息
- 索引文件：存索引数据

第4章会看到专业的文件组织方式。

## Java实战Demo

### Demo目标

实现一个**基于文件的KV存储引擎**，数据持久化到磁盘。包含：
1. 文件写入（序列化）
2. 文件读取（反序列化）
3. 随机访问
4. 数据恢复（重启后能读回数据）

### 项目结构

```
chapter-03-file-storage/demo/
├── pom.xml
└── src/main/java/com/ourdatabase/storage/
    ├── 文件存储引擎.java       (核心：基于文件的存储引擎)
    ├── 行数据序列化器.java      (把数据行转换为字节)
    └── 文件存储演示.java        (主程序，演示完整的读写恢复流程)
```

### 运行步骤

```bash
cd chapter-03-file-storage/demo
mvn compile
mvn exec:java -Dexec.mainClass="com.ourdatabase.storage.文件存储演示"
```
