    第5章：缓冲区管理·内存优化核心原理¶

    章节定位¶

    本章学什么？¶

    第4章学会了用数据页组织数据，但每次读写都要操作磁盘，非常慢。本章学习数据库最核心的性能优化手段——缓冲区池（Buffer Pool）。

    你将学习： 1. 什么是Buffer Pool？为什么它能大幅提升性能？ 2. LRU淘汰算法（最常用最少使用策略） 3. 脏页管理（修改过的页如何写回磁盘） 4. 缓冲区命中率的概念

    和前后章节的关联¶

    第4章(数据页) → 【第5章(缓冲池)】→ 第6-7章(B+树索引)

    详尽理论¶

    一、概念解释¶

    1.1 为什么需要Buffer Pool？¶

    计算机存储的速度差异：

    存储介质 访问速度 相对比值
    CPU寄存器 0.3 ns 即时
    L1缓存 1 ns 3倍
    内存（RAM） 100 ns 300倍
    SSD（固态硬盘） 100,000 ns 300,000倍
    HDD（机械硬盘） 10,000,000 ns 30,000,000倍

    核心问题：磁盘太慢了！每次读一行数据都去读磁盘，性能无法接受。

    解决方案：在内存中开辟一大块空间（Buffer Pool），把常用的数据页缓存在里面。

    1.2 Buffer Pool是什么？¶

    Buffer Pool是数据库启动时在内存中分配的一大块连续空间，用于缓存磁盘上的数据页。

    ┌─────────────────────────────────────┐
│            内存（RAM）                │
│  ┌───────────────────────────────┐  │
│  │        Buffer Pool            │  │
│  │  ┌─────┐ ┌─────┐ ┌─────┐     │  │
│  │  │ 页3  │ │ 页7  │ │ 页1  │     │  │
│  │  │(缓存)│ │(缓存)│ │(缓存)│ ... │  │
│  │  └─────┘ └─────┘ └─────┘     │  │
│  │  共1000个页槽位               │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
              ↕ 缓存换入/换出
┌─────────────────────────────────────┐
│            磁盘                      │
│  页0 │ 页1 │ 页2 │ 页3 │ 页4 │ ... │
└─────────────────────────────────────┘

    1.3 核心概念：命中与未命中¶

    • 缓存命中（Cache Hit）：要访问的页已经在Buffer Pool中 → 直接从内存读，很快！
    • 缓存未命中（Cache Miss）：要访问的页不在Buffer Pool中 → 必须从磁盘读，慢！

    命中率 = 缓存命中次数 / 总访问次数

    这是衡量Buffer Pool效率的核心指标。命中率越高，数据库性能越好。

    二、原理详解¶

    2.1 LRU淘汰算法¶

    当Buffer Pool满了、需要加载新页时，必须淘汰一个旧页为新页腾出空间。

    LRU（Least Recently Used，最近最少使用）算法的核心思想： - 如果某个页最近被访问过，那它短期内很可能再次被访问 - 淘汰"最久没有被访问"的页

    LRU链表（最近使用 → 最久未使用）：
 [页3] ↔ [页7] ↔ [页1] ↔ [页5] ↔ [页2]
  ↑ 最近访问            ↑ 最久未访问
  (保留)                    (优先淘汰)

    每次访问一个页时，把它移到链表头部。当需要淘汰时，淘汰链表尾部的页。

    2.2 脏页（Dirty Page）和干净页（Clean Page）¶

    • 脏页：在Buffer Pool中被修改过、但还没写回磁盘的页
    • 干净页：和磁盘上内容完全一样的页
    读取页（磁盘→内存）：    变为干净页
修改页中的数据：          变为脏页
将脏页写回磁盘（Flush）： 变为干净页

    关键：淘汰脏页时，必须先把它写回磁盘，否则修改会丢失！

    2.3 改进的LRU：冷热分离¶

    MySQL InnoDB使用改进版的LRU链表，分为热区和冷区（5/8 + 3/8分割）：

    LRU链表：
 [热区（5/8）...............│ 冷区（3/8）............]
  新页          中间点      旧页(优先淘汰)
    • 第一次加载的页放入冷区头部（不是热区！）
    • 如果在冷区停留够久且再次被访问，才晋升到热区
    • 防止全表扫描把热数据冲掉

    三、常见误区¶

    误区1：Buffer Pool越大越好¶

    错误：把Buffer Pool设成物理内存的90%。

    正确：Buffer Pool太大 → 操作系统内存不足 → 系统开始swap（把内存内容交换到磁盘），反而更慢。通常设为物理内存的50%-80%。

    误区2：命中率100%最好¶

    错误：命中率越高越好，要追求100%。

    正确：命中率100%意味着数据全在内存里，但数据总量可能远大于内存。追求合理的命中率（比如99%以上），而不是绝对100%。

    Java实战Demo¶

    Demo目标¶

    实现一个带LRU淘汰策略的Buffer Pool。

    项目结构¶

    chapter-05-buffer-pool/demo/
├── pom.xml
└── src/main/java/com/ourdatabase/buffer/
    ├── 缓冲池.java       (核心)
    ├── 缓冲页.java       (Buffer Pool中的页)
    └── 缓冲池演示.java    (主程序)

    运行步骤¶

    cd chapter-05-buffer-pool/demo
mvn compile
mvn exec:java -Dexec.mainClass="com.ourdatabase.buffer.缓冲池演示"

    本章总结¶

    序号 知识点 说明
    1 Buffer Pool 内存中的页缓存，大幅减少磁盘IO
    2 缓存命中率 核心性能指标
    3 LRU淘汰 淘汰最久未使用的页
    4 脏页 修改过但未写回磁盘的页
    5 冷热分离 防止扫描操作污染缓存
